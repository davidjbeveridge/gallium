What Gallium takes over

Gallium is a skill for your agent and an engine that runs on your computer. The skill sends the job to the engine. One request from your agent can cover opening a page, following links, waiting for results, and checking the answer.

Read a public document

“Find the minimum Node version in this install guide and quote the line.”

Gallium can fetch the text directly over HTTPS, saving a trip through Chrome. The reply includes the passage and source URL.

Find something on a live site

“Find Saturday's opening time in this museum's public calendar.”

If the fetched text comes up short, Gallium can switch to Chrome and keep looking. It can follow links, use tabs on the page, or search. In the quote demo, one task request covered three Next clicks.

Make a change and check it saved

“Set my display name to Ada and check that it saved.”

For an account you've configured, Gallium can run the change and read back the saved value. If a save might have gone through before a connection dropped, it checks the current value before retrying.

Take over a step yourself

“Pause this task and give me the tab.”

In a configured Chrome workflow, you can take control and hand it back when you're ready. The pause survives a restart, so you can pick up the same job later.

How Gallium runs a task

The CLI and MCP server share a local service by default. Give it a goal and an operation ID. The service picks the route and keeps the receipt in SQLite.

Start with the request

A public lookup can start with a direct HTTPS read. If the text comes up short, Gallium can open the site in Chrome. Ask it to use the interface and it starts in Chrome.

For a configured account, the Jev model checks which procedures fit the goal. The controller uses the first eligible route in this order.

  1. Direct HTTP request
  2. Request inside the signed-in Chrome session
  3. Interaction with the page
Read the task controller

Work from the page

In Chrome, Jev can choose a link or control that Gallium has observed. Gallium checks the choice, acts, and looks again. If the page shows a loading state, it waits.

Public exploration stays on the same site origin for up to 12 observations or 60 seconds. Gallium stops when the next action has an unclear effect. Before it returns a passage, it checks that the text is still on the page.

Read the exploration loop

Check the result before a retry

A click can go through just before a connection drops. Gallium checks the saved state before it tries that write again. Reuse the same operation ID and inputs so it can pick up the previous receipt and procedure.

Read the journal schema

Take over in Chrome

Pause a configured workflow to finish a step yourself. Gallium releases the debugger and keeps the pause through a restart. Hand control back, then repeat the original request. Gallium checks whether you already finished.

The service queues Chrome work and requests on the same account. Independent HTTP reads can run in parallel.

Install Gallium

You'll need Git and Node.js 24 or later to run the engine.

Set up the engine

Run this in a terminal. The installer adds the CLI and routing skill. If you have the Codex CLI, it registers the MCP server too. Open a new chat to load it.

Terminal 
git clone https://github.com/davidjbeveridge/gallium.git &&
cd gallium &&
npm ci &&
npm run install:local

Add the skill to a project

Run this where you use your agent. The skill uses the CLI or MCP server from the engine setup.

Terminal 
npx skills add davidjbeveridge/gallium

Open a new agent session to load the skill. To use Gallium by default, add Use the Gallium skill for web tasks. to your project's agent instructions.

Try the local demo

The demo uses a temporary test profile and runs with Git and Node alone. It checks a save, repeats the request to show what happens to a duplicate, then pauses a second update through a restart. If you've already cloned the repo, run npm run demo from the checkout.

Terminal 
git clone https://github.com/davidjbeveridge/gallium.git &&
cd gallium &&
npm run demo

Look up a public document

Ask your agent to use Gallium, then give it the question and the public URL. You can make the same request in a terminal. First, configure the Jev router. The Chrome bridge adds access to live pages. Router setup · Chrome bridge setup

Terminal 
~/.local/bin/gallium task --operation rfc418 \
  --goal 'What does HTTP status 418 mean in this document?' \
  --target https://www.rfc-editor.org/rfc/rfc2324.txt

Send the lookup over MCP

Pass these arguments to web_task.

JSON 
{
  "operationId": "rfc418",
  "goal": "What does HTTP status 418 mean in this document?",
  "target": "https://www.rfc-editor.org/rfc/rfc2324.txt"
}

Before you run it

When do I need Chrome?

Live page tasks and requests inside a browser session use desktop Chrome with the Gallium bridge enabled. The demo and direct HTTPS reads run from the local engine.

Can it work on a site I'm signed into?

Yes, with a procedure that names the account, the allowed actions, and the result to check. Gallium can use the existing session in the Chrome tab you enabled.

What if a public site asks me to sign in?

A public lookup stops at sign-in and challenge pages and tells your agent what it hit. Use a configured account workflow for signed-in work. That lets you pause and take over a step in Chrome.

Do I need a model key?

Public lookups and goal-based procedure matching use Jev through OpenRouter. The fixture demo and procedures with fixed steps can run locally without a model call.

What gets sent to the model?

The engine and journal live on your machine. When a task uses Jev, Gallium sends the goal and the page excerpts, controls, or nonsecret procedure details it needs to make a decision. The browser uses cookies and CSRF tokens inside the tab.

Can I use another MCP client?

Configure it to launch node bin/mcp.mjs from the checkout. Gallium exposes web_task for goals, web_status for receipts, and web_control for pause and handback.
